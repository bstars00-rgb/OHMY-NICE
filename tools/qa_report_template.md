### 3.1 자체 적대적 점검에서 찾은 결함(루프 3)

독립 재검증을 요청한 4개 에이전트(금액·원장, 등급·사실·경보, 저장소·설정·보안, 화면·CSV·테스트 약점)가 모두 응답 없이 중단되어, 같은 범위를 제가 직접 공격자 관점의 스크립트로 점검했다. **이것은 독립 검증이 아니다.** 점검 항목: 중복 변형 12종(표기·시간대·통화 대소문자·금액 형식·BOM/CRLF), 대사 기준일, 검증자 이름 15종, 설정 이상값 13종, 저장 데이터 변조 10종, CSV 수식 주입 14종, 11개 필드에 넣은 HTML 주입 페이로드로 8개 화면 한/영 렌더링, 영어 화면의 한글 문자열.

문제 없음: 중복 변형 전부 차단, 설정 이상값 전부 거부(앱 정상 유지), HTML 주입 0건, 영어 화면의 한글은 담당자가 입력한 데이터뿐이고 UI 문자열 누락은 없음.

|---|---|---|---|

남은 한계: 증빙 참조번호는 4자 이상이면 내용(`xxxx`)을 가리지 않고 받아들인다. 증빙의 진위는 사람이 확인해야 한다. 호텔이 확인한 뒤 과거 날짜로 소급 입력한 거래는 대사 불일치(MAJOR)로 잡히는데, 이는 의도한 동작이다.

### 3.2 독립 재검증(루프 4)에서 나온 결함

독립 리뷰어 4명(별도 에이전트, 읽기 전용)이 영역을 나눠 직접 재현 스크립트를 썼다: ① 원장·대사·금액 산식, ② 등급·사실·경보, ③ 저장소·설정·권한, ④ 화면·CSV·SG·테스트 약점. 에이전트가 길게 멈추던 문제는 영역을 잘게 나누고 스크립트 길이·호출 횟수를 제한해서 풀었다. 4명 모두 결과를 냈다.

독립적으로 문제 없음으로 확인된 것: 금액 산식 전부(평균·한도·소진일을 BigInt 기준값과 비교. 1 최소단위, USD 센트, 9e14 VND 포함), 등급 부풀리기 경로 없음(12가지 우회 시도 실패, 미확인 항목 제외·NR 규칙 정상), 권한(결재 결정은 CEO만, 작성자 본인 거부, 원장은 `ledger.write`·`import`로만 변경), `__proto__` 등 ID 오염 없음, 저장 실패 롤백, HTML 주입 페이로드 어떤 화면에도 미노출, CSV 수식 주입 방어.

### 3.3 수정에 대한 독립 재확인(루프 5)

루프 4에서 고친 12건을 별도 리뷰어 3명(읽기 전용)이 다시 깨뜨려 봤다: ① 중복 방지·대사 기준일, ② 검증된 사실·경보·불러올 때 감사 대조, ③ SG·한도·설정·문구. 12건 중 **6건은 완전히 고쳐졌고 6건은 일부만** 고쳐졌다. 리뷰어는 수정 과정에서 생긴 새 결함도 찾았다.

완전히 고쳐짐으로 확인: G4 대사 기준일(KST 23:59:59와 00:00 경계 포함), G3 검증된 사실의 잠금(우회 시도 8가지 실패), G5 치명 경보 기각 차단과 보류 유지, G7 SG 만기 처리(경계 포함), G8 한도 산정 불가(NaN 없음), 금액 산식 재대조.

### 5.1.3 해석

- 범위 조정 기준으로 기획 97.7은 합격선(97) 이상이고 QA 94.0은 미달이다. 합격 조건은 둘 다 97 이상이므로 판정은 FAIL이다. 기존 전체 기준은 기획·QA 모두 86이다.
- 남은 감점은 모두 지금 할 수 있는 일이다. 기획 2점(03·06번 화면별 기능 검토 1점 등), QA 5.5점(루프 6 수정의 독립 재확인 5점, 장시간 구동 0.5점).
- 독립 재확인을 할 때마다 직전 수정의 일부가 불완전했고(루프 4: 12건 중 6건, 루프 5: 9건 중 6건), 이번 수정(I1~I5)도 같은 확인을 받지 않았다. 독립 확인에서 결함이 하나도 나오지 않는 라운드가 나올 때까지는 QA 점수를 올리지 않는다.
- 제외 항목은 "문제 없음"이 아니라 "지금 검증할 수 없음"이다. 운영 전에는 반드시 다시 평가해야 한다.
